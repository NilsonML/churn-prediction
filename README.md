# Churn Prediction

End-to-end pipeline for customer churn prediction: data generation → feature engineering → three gradient-boosting models (CatBoost, LightGBM, XGBoost) → evaluation with SHAP explanations.

The focus is on a **leak-free, reproducible pipeline**: every step that learns from data (feature thresholds, encoders, model) lives inside one scikit-learn `Pipeline`, so it is fitted on the training set only and works unchanged in cross-validation and inference.

## Results

| Model | ROC-AUC | F1 | Accuracy |
|---|---|---|---|
| CatBoost | 0.9956 | 0.961 | 0.960 |
| LightGBM | 0.9954 | 0.961 | 0.960 |
| XGBoost | 0.9953 | 0.960 | 0.959 |

*Hold-out test set, 20 000 customers. Computed before the pipeline refactor (see "Changelog"); re-run `python main.py --all` to refresh.*

**How to read these numbers.** The data is synthetic and churn is generated by a fixed rule (short tenure + high price + month-to-month contract + few services + noise > 0.5). A ROC-AUC of 0.995 means the models recovered that rule, not that the task is solved. A quick check with plain logistic regression gives ~0.99 too, so boosting adds little here. The value of the project is the pipeline, not the score.

## Pipeline

```
raw features ──► ChurnFeatureBuilder ──► ColumnTransformer ──► classifier
                 (fit: learns thresholds    (One-Hot for categories,   (CatBoost / LightGBM /
                  on train only)             numbers passed through)    XGBoost)
```

Key design decisions:

| Decision | Why |
|---|---|
| Feature engineering as a scikit-learn transformer (`fit` / `transform`) | Thresholds like "top-25% monthly charge" are learned on train and reused on test. Computing them on the test set separately would leak test statistics. |
| One `build_pipeline(name)` for all models | Adding a model is one line in `MODEL_FACTORIES`, not a copy of a 30-line function. |
| No `StandardScaler` | Tree models split on thresholds; monotonic scaling doesn't change them. |
| Lazy imports of boosting libraries | Tests run without CatBoost / LightGBM / XGBoost installed. |
| Stratified train/test split | Same churn rate in both sets. |

## Project structure

```
├── main.py                    # CLI: --generate / --train / --evaluate / --all
├── config.py                  # paths, hyperparameters, split settings
├── src/
│   ├── data_processing.py     # synthetic data generation, train/test split
│   ├── feature_engineering.py # ChurnFeatureBuilder (sklearn transformer)
│   ├── models.py              # build_pipeline(), model registry
│   ├── train.py               # fit and save pipelines
│   └── evaluate.py            # metrics, confusion matrices, ROC, SHAP
├── tests/                     # features, leakage, pipeline, cross-validation
└── models/                    # saved plots and metrics (*.pkl are git-ignored)
```

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python main.py --all      # generate data → train → evaluate
pytest                    # 8 tests, ~10 s
```

Individual steps: `python main.py --generate`, `--train`, `--evaluate`.

## Changelog

- Fixed `is_middle_age`: `(age) & (age <= 60)` was a bitwise AND (`age & 1`), so the flag meant "odd age up to 60".
- Moved feature engineering into the pipeline: quantile thresholds were recomputed on the test set.
- Removed `early_stopping_rounds` (had no effect without an eval set) and an invalid XGBoost `verbose` argument.
- Removed training logs and generated data from git; added tests.
